## 자동 실행 권한 설정 /permissions

프로젝트 단위 권한은 .claude/setings,local.json에 생성되며, 사용자 설정은 ~/.claude/settings,json에 생성됩니다.

권한은 파일 기반 설정으로 관리되며, **적용 우선순위**는 다음과 같습니다(위로 갈수록 강함):

1. **엔터프라이즈 정책**(관리자 강제)
2. **명령줄 인수**
3. **로컬 프로젝트**: `.claude/settings.local.json`
4. **공유 프로젝트**: `.claude/settings.json`
5. **사용자 설정**: `~/.claude/settings.json`

엔터프라이즈 환경에선 조직 정책 파일(예: macOS의 `/Library/Application Support/ClaudeCode/managed-settings.json`)이 **사용자/프로젝트 설정을 덮어** 일관된 보안을 보장합니다



### A. /permissions 화면 여는 법

1. 터미널에서 Claude Code 실행

```
claude
```

1. 프롬프트에서 슬래시 명령 입력

```
/permissions
```

→ 현재 **Allow/Ask/Deny 규칙**과 **출처 settings.json**을 확인/편집합니다. 필요시 Add/Remove/Edit 해보세요. [docs.claude.com](https://docs.claude.com/en/docs/claude-code/iam)

> 참고: 환경 전반 설정은 `/config`에서 탭 UI로 관리할 수 있습니다. [docs.claude.com](https://docs.claude.com/en/docs/claude-code/settings?utm_source=chatgpt.com)

### B. 프로젝트 전용 설정 체크인(권장)

프로젝트 루트에 `.claude/settings.json`을 두고 팀과 공유하세요:

```
{
  "defaultMode": "default",
  "allow": [
    "WebFetch(domain:api.mycompany.com)",
    "Bash(npm run test:*)"
  ],
  "ask": [
    "Bash(npm run build)"
  ],
  "deny": [
    "Bash(rm -rf:*)"
  ],
  "additionalDirectories": [
    "./docs",
    "~/work/shared-libs"
  ],
  "read": [
    "src/**",
    "README.md"
  ],
  "edit": [
    "src/**",
    "package.json"
  ]
}
```

- 팀원은 `/permissions`에서 동일하게 규칙을 확인 가능.
- 민감 작업은 `ask`나 `deny`로 막고, CI 등 자동화는 `allow`로 최소 범위만 열어 주세요. (규칙·모드·디렉터리 항목은 /permissions UI와 동기화됩니다.) [docs.claude.com](https://docs.claude.com/ko/docs/claude-code/iam)



## CLAUDE.md

단순한 마크다운 파일로, 이 파일을 읽어 아키텍처 코딩 규칙 작업 절차 등을 깊이 있게 파악한다. 

이것이 있으면, 프로젝트의 복잡한 내용을 반복해서 설명할 필요가 없다. 



#로 제목별로 적당한 지시를 해두면 된다 

앤트로픽은 이런 내용을 CLAUDE.md에 작성하면 좋다고 이야기합니다.

- ﻿﻿자주 사용하는 bash 명령어

- ﻿﻿핵심 파일 및 유틸리티 함수

- ﻿﻿코드 스타일 가이드라인

- ﻿﻿테스트 지침

- ﻿﻿저장소 에티켓

- ﻿﻿예 : 브랜치 이름 지정, 병합(merge), 리베이스(rebase) 등

- ﻿﻿개발자 환경 설정

- ﻿﻿예: pyenv 사용, 작동하는 컴파일러 등

- ﻿﻿프로젝트에 특정한 예상치 못한 동작이나 경고

- 클로드 코드가 기억했으면 하는 기타 정보

  이 외에도 저는 다음을 추천합니다.

  - ﻿﻿일괄적으로 사용하고 싶은 라이브러리에 대한 정보
  - ﻿﻿또는 아키텍처에 대한 정보



기술과 아키텍처, 라이브러리도 잊지말자. 



또한 목적에 따라 3가지로 분류하여 사용 가능하다

* 프로젝트 메모리 (./claude.md)
  * 프로젝트 루트에 위치하며 팀 전체에 적용할 규칙과 정보를 담는다
  * 프로젝트 아키텍처: 프로젝트 구조와 핵심 구성 요소에 대한 상위 수준의 설명 
  * 코딩 표준 : 스타일 가이드, 명명 규칙, 서식 규칙
  * 일반적인 워크플로 : 애플리케이션 빌드, 테스트 배포 지침 
* 로컬 프로젝트 메모리(./claude.local.md) : 개인적인 프로젝트 관련 파일. 팀과 공유하지 않고, gitignore에 추가
  * ﻿﻿샌드박스 URL
  * ﻿﻿개인 API 키 또는 테스트 데이터
  * ﻿﻿자신에게 유용한 맞춤형 명령어
* 사용자 메모리 (~/.claude/CLAUDE.md)
  * 홈 디렉터리에 위치. 모든 프로젝트에 적용되는 전역 설정을 저장
  * 일반적인 코드 스타일 선호도
  * 개인 도구를 위한 단축키.

## 커스텀 슬래시 커맨드 사용하기

자주 사용하는 프롬프트를 슬래시 커맨드로 만들어서 간편하게 사용 가능하다

커스텀 슬래시 커맨드는 기본 슬래시 커맨드와 마찬가지로 Y'를 입력하면 사용할 수 있습니다. prefix.

command-name, arguments 세 가지 요소로 이루어져 있으며 다음과 같은 형태를 띕니다.
```
/<prefix>:<command-name> [arguments]
```

* prefix : 커스텀 커맨드의 스코프. 프로젝트 : project, 사용자 : user
* command-name : 커맨드가 정의된 마크다운 파일 이름
* arguemtns : 커맨드에 제공할 선택적 매개변수

프로젝트 커스텀 슬래시 커맨드는 .claude/commands 아래에, 사용자는 ~/.c;aude/commands에 있다



# MCP

3가지 방식이 있음. 로컬 서버 방식, SSE 방식, HTTP 방식

대부분 로컬 서버 방식임



커맨드로 추가하지

```
claude mcp add <name> command [args]
```

```
{
  "mcpServers": {
    "context7": {
      "type": "stdio",
      "command": "прх",
      "args": [
        "-y",
        "@upstash/context7-mcp"
      ],
      "env": {}
    }
  }
}
// 파일명 : .mcp.json 으로 추가됌. 
명령어 : claude mcp add context7 -- npx -y @upstash/context7-mcp
```



sse 커맨드로 추가하기

```
claude mcp add -transport sse <name> <command> [args..]

claude mcp add --transport sse context7 https://mcp.context7.com/sse
```

http 추가하기

```
claude mcp add -transport http context7 https://mcp.context7.com/ss
```

## playwright mcp 데모

1) 가장 쉬운 설치(권장): `claude mcp add` 한 줄

터미널에서 아래 한 줄만 실행하면 Claude가 Playwright MCP를 자동 등록합니다.

```
claude mcp add playwright npx @playwright/mcp@latest
```

→ 이 명령은 공식 가이드에 명시된 **정석**이에요. [GitHub](https://github.com/microsoft/playwright-mcp)

설치 확인:

```
claude mcp list
```

여기에 `playwright`가 보이면 정상입니다. (보이지 않으면 한 번 더 실행)

> 참고: 같은 README에 **표준 설정(JSON) 스니펫**과 여러 클라이언트(Claude Code, Desktop 등)에서의 설정 예시가 정리돼 있어요. [GitHub](https://github.com/microsoft/playwright-mcp)

2) 수동 설정(대안, 필요할 때만)

직접 설정 파일로 붙이고 싶다면, 작업 디렉토리(또는 사용자 설정) 아래에 다음 형식으로 넣습니다.

```
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}
```

이 JSON 스니펫이 **표준 구성**입니다. (README “Standard config”) [GitHub](https://github.com/microsoft/playwright-mcp)

3) 브라우저 바이너리 점검(선택)

대부분 자동으로 되지만, 만약 브라우저 없다는 오류가 뜨면:

```
npx playwright install chromium
```

(Playwright MCP 자체는 `@playwright/mcp`로 제공되고, **Node 18+ 필요**가 공식 요구사항입니다.) [GitHub](https://github.com/microsoft/playwright-mcp)

4) Claude에서 실제 사용

Claude(코드/데스크톱)에서 그냥 자연어로 지시하세요:

```
Use the Playwright MCP to open Chromium.
Go to https://example.com
Extract the page title and return it as JSON.
```

또는 한국어로:

```
Playwright MCP로 Chromium 열고,
https://news.ycombinator.com 로 이동,
기사 제목들을 수집해서 JSON 배열로 반환해줘.
```

> 이 MCP는 스크린샷 기반이 아니라 **접근성 스냅샷(구조화 데이터)** 로 동작해 **빠르고 결정적**이에요. 공식 README의 특징에 요약돼 있습니다. [GitHub](https://github.com/microsoft/playwright-mcp)

## postgresql 데모 

```
cat > .mcp.json <<'JSON'
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": [
        "@modelcontextprotocol/server-postgres",
        "postgresql://postgres:postgres@localhost:5432/oww_local?sslmode=disable"
      ]
    }
  }
}
JSON
```

* 위 명령어를 작업 디렉토리에서 사용하고, claude에 접속해서 사용하면 된다. 



```
claude mcp add postgres \
  npx @modelcontextprotocol/server-postgres \
  "postgresql://postgres:postgres@localhost:5432/oww_local?sslmode=disable"
```

설명:

- `claude mcp add postgres` : MCP 이름을 `postgres`로 등록
- `npx @modelcontextprotocol/server-postgres` : 해당 MCP 서버 패키지를 `npx`로 실행
- 마지막 인자는 PostgreSQL 접속 문자열(여기서는 기본 DB `postgres` 사용)

# PRD 와 실행 계획

prod : product requirements document. 제품 요구사항 문서

PRD의 질문

- ﻿﻿어떤 사용자를 위해 만드는가?
- ﻿﻿어떤 문제를 해결해주는가?
- ﻿﻿비즈니스 측면에서 어떤 이득이 있는가?
- ﻿﻿어떤 기능과 경험을 제공해야 하는가?
- ﻿﻿사용자는 어떤 경험을 하게 되는가?
- ﻿﻿우리는 무엇을(What), 왜(Why) 만드는가?

```
🛍️ 쇼핑몰 사이트 구축 프로젝트 PRD
1. 프로젝트명

소상공인을 위한 간편 쇼핑몰 솔루션

2. 문제 정의 (Why)

많은 소상공인이 온라인으로 제품을 판매하고 싶어 하지만,
웹사이트 제작의 높은 비용과 기술적 복잡성 때문에 시장 진출에 어려움을 겪고 있습니다.
이로 인해 성장의 기회를 놓치고 있습니다.

3. 목표 및 성공 지표

a. 목표:
코딩 지식이 없는 소상공인도 몇 시간 안에 자신만의 온라인 스토어를 개설하고 운영할 수 있는
```

# Claude code hook

도구 사용 전과 후, 알림 등에 사용

### **클로드 코드 훅(Claude Code Hooks) 설정 안내**

클로드 코드 훅은 **JSON 파일** 형태로 등록할 수 있으며,

다른 설정과 마찬가지로 **로컬**, **프로젝트별**, **사용자별** 설정이 가능함.

### **설정 종류 및 위치**

| **설정 구분**          | **설명**                | **파일 경로**               |
| ---------------------- | ----------------------- | --------------------------- |
| **사용자 설정**        | 전체 사용자 공통 설정   | ~/.claude/settings.json     |
| **프로젝트 설정**      | 해당 프로젝트 전용 설정 | .claude/settings.json       |
| **로컬 프로젝트 설정** | 커밋 제외용 로컬 설정   | .claude/settings.local.json |

### **JSON 구조 예시**

```
{
  "hooks": {
    "<EventName>": [
      {
        "matcher": "<ToolPattern>",
        "hooks": [
          {
            "type": "<command>",
            "command": "<your-command-here>"
          }
        ]
      }
    ]
  }
}
```

### 예시 설명

- **`EventName`**: 훅이 실행될 이벤트 이름  
  예: `onSave`, `onRun`, `onCommit`, `PreToolUse`, `PostToolUse` 등  

- **`matcher`**: 도구 이름과 일치하는 **패턴**  
  - 대소문자를 **구분함**  
  - `PreToolUse` 및 `PostToolUse` 이벤트에서만 사용됨  
  - 단순 문자열은 **정확히 일치**  
  - **정규식(Regex)** 을 지원함  
  - 다음은 `matcher` 예시와 의미:

    | matcher 값                           | 설명                                                 |
    | ------------------------------------ | ---------------------------------------------------- |
    | `"Bash"`                             | Claude Code가 Bash Tool을 사용할 때 훅 실행          |
    | `"Edit"` / `"MultiEdit"` / `"Write"` | 단일 파일 수정, 여러 파일 수정, 파일 생성 시 훅 실행 |
    | 정규식 예: `"^Python.*"`             | Python으로 시작하는 도구 이름에 매칭                 |

  - **예시**
    - `matcher: "Bash"` → Bash 실행 시에만 훅 실행  
    - `matcher: "Edit" | "MultiEdit" | "Write"` → 파일 수정 또는 생성 시 훅 실행  

- **`hooks`**: `matcher`가 일치할 때 실행할 명령의 배열  

- **`type`**: 현재 `"command"`만 지원됨  

- **`command`**: 실행할 **bash 명령어**  
  - 환경 변수 `SCLAUDE_PROJECT_DIR` 사용 가능  

- **`timeout`**: *(선택사항)* 명령이 취소되기 전까지 실행될 시간(초)  

- `UserPromptSubmit`, `Notification`, `Stop`, `SubagentStop` 과 같은  
  **matcher를 사용하지 않는 이벤트**에서는 `matcher` 필드를 생략 가능







1. **모드 변경하기**

   Shift + Tab을 눌러 일반 모드, 자동 승인 모드, 플래닝 모드 간 전환할 수 있음.

2. **플래닝 모드 활용하기**

   클로드 코드에게 직접 작업을 시키기 전, 플래닝 모드로 상세한 작업 계획을 받아보는 것이 좋음.

3. **YOLO 모드 사용하기**

   한 번에 실행 가능한 단일 작업이라면 YOLO 모드를 통해 즉시 실행하면 시간을 절약할 수 있음.

4. **기능 물어보기**

   “풀 리퀘스트 만들 수 있어?” 등 궁금한 기능을 클로드 코드에게 직접 물어볼 수 있음.

5. **프로젝트 분석 요청하기**

   기억나지 않거나 이해하기 어려운 부분이 있다면 클로드 코드에게 프로젝트 분석을 요청.

6. **연동 방법 요청하기**

   외부 API나 서비스를 직접 연결할 때, 클로드 코드에게 연동 방법을 물어보기.

7. **릴리즈 노트 확인하기**

   release 명령으로 주기적으로 확인. 자동 업데이트로 새로운 기능이 추가될 수 있음.

8. **Anthropic 상태 구독하기**

   Anthropic Status 페이지에서 클로드 코드 및 서비스 상태를 RSS, Slack 등으로 구독 가능.

9. **CLAUDE.md 주기적 업데이트하기**

   프로젝트 요구사항에 맞게 CLAUDE.md 파일을 주기적으로 갱신해야 함.

10. **CLAUDE.md 요약하기**

    문서가 너무 길면 콘텍스트 활용에 불리하므로 주기적으로 요약 및 정리 필요.

11. **CLAUDE.md 하위 폴더 생성하기**

    프로젝트 하위 폴더에도 CLAUDE.md를 생성할 수 있으며, 해당 폴더 탐색 시 자동 주입됨.

12. **빠르게 메모리 추가하기**

    \#을 입력해 CLAUDE.md에 추가하고 싶은 내용을 빠르게 기록 가능.

13. **경로 자동완성 활용하기**

    파일 경로 입력 시 Tab 키로 자동 완성 기능을 활용할 수 있음.

14. **초기화하기**

    프로젝트 첫 실행 시 init 명령으로 초기화해야 함.

    클로드 코드가 프로젝트를 분석하고 적절한 CLAUDE.md 생성함.

15. **모델 확인하기**

    실행 전 model 명령으로 모델 확인 필요.

    Opus 모델은 토큰 사용량이 많으므로 주의.

16. **프롬프트 즉시 실행하기**

    예: claude "issue-20 해결해줘" → 실행과 동시에 프롬프트 실행.

17. **헤드리스 모드 실행하기**

    -p 플래그로 헤드리스 모드 실행 가능.

    예: claude -p "프로젝트 분석해줘".

18. **데이터 파이핑하기**

    헤드리스 실행 시 데이터 입력 파이핑 가능.

    예: cat test.md | claude -p "이 마크다운을 분석해줘".

19. **파일 참조하기**

    @를 사용해 특정 파일을 참조하면 정확도가 향상됨.

20. **Shift 드래그하기**

    파일을 드래그 앤 드롭할 때 Shift를 누르면 정상적으로 참조됨.

21. **이미지 활용하기**

    이미지를 드래그 앤 드롭하거나 Ctrl + V로 주입 가능.

22. **스크린샷 활용하기**

    결과물이 마음에 들지 않을 때 스크린샷을 찍어 이미지로 주입.

23. **ASCII 코드로 디자인 확인하기**

    디자인 작업 전, ASCII 코드 기반의 디자인 목업 요청 가능.

24. **Figma MCP 활용하기**

    Figma MCP를 통해 Figma 디자인을 코드로 쉽게 변환 가능.

25. **클로드 코드 훅 사용하기**

    작업 완료 시 자동으로 테스트, 알림, 린트 등을 실행하도록 훅 설정.

26. **자연어로 테스트 자동화하기**

    테스트 조건을 자연어로 설명하면 클로드 코드가 자동으로 테스트 생성.

27. **QA 자동화하기**

    테스트, 린트, 빌드 등을 자동 실행하고 결과에 따라 코드 개선 가능.

28. **QA 목표 지정하기**

    예: “유닛 테스트 80% 이상 통과” 등 목표를 설정하면 자동 반복 수행 가능.

29. **E2E 테스트하기**

    Puppeteer나 Playwright를 활용해 종단 간 테스트(E2E) 실행.

30. **엣지 케이스 요청하기**

    테스트 코드 작성 시 엣지 케이스를 포함하도록 요청.

31. **콘텍스트 주입하기**

    작업 전 프로젝트 관련 콘텍스트를 충분히 제공해야 정확한 결과 가능.

32. **콘텍스트 클리어하기**

    /clear 명령으로 대화 콘텍스트를 초기화.

    완전히 다른 작업 시 오염 방지를 위해 자주 사용 권장.

33. **콘텍스트 컴팩트하기**

    /compact 명령으로 메모리 사용량 최적화.

    특정 작업 종료 후 직접 실행하는 것이 효율적.

34. **프롬프트 취소하기**

    잘못된 작업을 수행 중이라면 Esc로 즉시 취소.

35. **MCP 활용하기**

    MCP로 클로드 코드가 접근할 수 없는 외부 기능이나 데이터를 확장 가능.

36. **Context7 MCP 사용하기**

    최신 공식 문서를 검색해 클로드 코드에 자동 주입 가능.

37. **Supabase MCP 활용하기**

    Supabase 관련 데이터베이스 연동 및 쿼리 자동화 가능.

38. **Sequential Thinking MCP 사용하기**

    단계적 사고를 통해 더 정교한 추론 작업 수행 가능.

39. **TossPayments MCP 활용하기**

    대한민국 PG 중 최초 MCP로 결제 연동 작업을 단순화.

40. **디자인 컴포넌트 제작하기**

    본격적인 디자인 전 데모 페이지를 제작해 일관성 유지.

41. **웹사이트 URL 입력하기**

    클로드 코드가 웹사이트 정보를 검색해 참고할 수 있음.

42. **Playwright로 크롤링하기**

    마음에 드는 사이트의 테마를 JSON으로 정리해 재사용 가능.

43. **페르소나 제공하기**

    “너는 백엔드 개발자야” 등 역할을 지정하면 더 나은 결과 제공.

44. **PRD 먼저 작업하기**

    프로젝트 방향성을 명확히 하기 위해 상세한 PRD 작성 필요.

45. **워크트리 활용하기**

    독립된 브랜치에서 작업하여 메인 브랜치에 영향 없이 개발 가능.

46. **피드백 루프 활용하기**

    계획 → 작업 → 확인 과정을 자동화하여 지속적 개선 가능.

47. **여러 스텝에 걸쳐 작업하기**

    작업을 여러 단계로 나눠 점진적으로 개선하는 방식이 효율적임.

48. **여러 스텝 되돌리기**
