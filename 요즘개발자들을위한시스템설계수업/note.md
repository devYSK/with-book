# 요즘 개발자들을 위한 시스템 설계 수업



# 1장 시스템 설계의 기본



분산 소프트웨어 시스템은 여러 독립적 컴포넌트, 프로세스, 노드로 구성되며 서로 통신을 주고받으며 하나의 공동 목표를 달성하려고 동작한다. 

각 구성요소는 Remote Procedure Call 또는 Message, publish/subscribe 등으로 서로 소통한다.

주로 확장성, 가용성, 장애 허용이 중요한 대규모 애플리케이션을 구축할때 사용한다



## 상위 수준의 시스템 설계

설계시 고려사항

* 시스템 아키텍처
  * 모놀리식, 마이크로서비스, 이벤트드리븐
  * 설계시 요구사항에 적합한지 이유와 적합성을 분명하게 정의하고 선택해야함 
* 데이터 흐름
  * 데이터 수집 : 어떻게 가져올지, api나 스트리밍, 배치 등 
  * 저장 : 얼마나 자주 접근하는지, 검색 성능 중요한지, 일관성이 중요한지 등 고려
  * 처리 : 변환하거나 분석 요약하는 과정을 병목없이 어떻게 처리할지
  * 검색 : 응답시간, 캐싱, 부하분산 등을 고려 
* 확장성
  * 수직 확장성, 수평 확장성 
* 장애 허용 시스템 
  * 복제, 중복성, 점진적 성능 저하, 모니터링, 자가 복구 등이 중요하다 



코드 재작성 방법

1. 리팩터링 : 기능은 그대로, 코드 구조 재구성
2. 루프 언롤링 : 반복문을 개별 구문 여러개로 대체
3. 메모이제이션 : 이전 실행 결과를 저장해서 동일 결과 계산 



# 2장 분산시스템의 속성

일관성, 가용성, 파티션 허용성, 지연 시간, 내구성, 신뢰성, 장애 허용성, 확장성에 대해 아라보자

## 일관성

여러 노드에 데이터가 복제되고 분산되어 있더라도 시스템 네 모든 노드가 항상 동일한 상태나 데이터를 참조하도록 하는 개념.  2개의 일관성 유형이 있다.

* 강한 일관성 - String consistency
* 최종 일관성 - eventual consistency

### 강한 일관성

모든 노드가 공유하고 있는 데이터 업데이트를 동일한 순서로 처리하도록 보장하는 특성. 엄격한 동기화와 작업 순서가 유지된다. 

분산 시스템에서는 여러 노드가 동시에 작업을 처리할 때 서로 데이터의 업데이트 순서를 늦추는 방법을 사용한다

* 분산 트랜잭션, 분산 잠금, 팩소스, 래프트 알고리즘 등

강한 일관성은 모든 노드가 동일한 순서에 따라 데이터를 업데이트하도록 보장한다

은행 시스템 같은 민감한 데이터를 다루는 곳에서 좋다. 

### 최종일관성

시스템 내에서 일시적이나마 데이터 불일치를 허용하지만, 시간이 지나면 모든 레플리카가 결국 동일한 상태에 도달하도록 하는 방식. 

최종 일관성 문제는 일시적으로 데이터가 불일치 하는것인데, 충돌 해결, 데이터 복제, 가십 프로토콜을 이용해 해결할 수 있다. 주로 비동기적으로 전달되고 업데이트 되어 처리된다. 

최종일관성의 장점은 가용성과 확장성을 높이고, 클라이언트에 더빠른응답을 줄 수 있다. 

### 가용성

가용성이란 시스템에 장애가 오류가 발생하더라도 사용자에게 서비스를 지속적으로 제공할 수 있는 능력.

예시로 디비를 복제하여 여러개 운영하는것이 가용성을 높이는것이라고 말할 수 있음. 

하지만 분산시키면 네트워크, 서버장애, 통신오류 등 문제가 발생할 수 있기때문에 안정적으로 유지하는것은 쉽지않다. 

**가용성을 보장하는 방식** 

* 다중화(중복성) : 여러 구성요소를 중복해 두어 일부 구성 요소에 장애 발생하더라도 계속 운영될 수 있게 하는 방식
* 복제(레플리케이션) : 데이터를 여러 노드에 복재해 시스템을 운영함
* 로드밸런싱 : 여러 노드에 작업량을 분배하여 특정 노드에 과부하가 걸리지 않도록 함 
* 장애 감지 및 복구 : ❤비트, 모니터링, 헬스 체크 등을 이용해서 장애 감지

## 파티션 허용성

네트워크 파티션이란, 네트워트 장애로 일부 노드나 컴포넌트가 시스템 다른 부분과 연결이 끊겨 서로 접근하거나 데이터를 주고받지 못하는 상태. 즉 여러 그룹이나 조각으로 나뉘어 고립된 상태. 



파티션 허용성이란, 네트워크 장애나 파티션이 발생해도 시스템이 정상적으로 동작할 수 있는 능력을 의미함

## 지연 시간

지연 시간은 요청에 대한 응답이 돌아오기까지 걸리는 시간. 즉 레이턴시

지연시간은 시스템 내 노드간 거리, 혼잡도, 노드당 ㅓ리시간, 데이터량에 따라 영향을 받음

줄이는 방법

* 네트워크 최적화 : 가까이 해서 홉을 줄인다.

* 캐싱 : 메모리, 콘텐츠, 디비 캐싱 등 처리시간을 줄임 
* 데이터 지역화 : 사용자와 가까운곳에 위ㅣ시킴
* 비동기 통신 : 병렬처리랑 논블로킹 등으로 처리 및 지연 시간을 줄일 수 있음

## 내구성

내구성이란 분산 시스템에서 장애나 오류가 발생하더라도 시스템에 저장된 데이터가 손실되지 않도록 보장하는 능력 

내구성을 유지하기 위해 복제나 백업 등을 사용함. 

내구성을 높이면 일관성을 유지하는데 시간이 더 걸릴 수 있다.
