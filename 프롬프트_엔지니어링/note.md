입력된 프롬프트의 구성에 따라 응답 결과가 크게 달라질 수 있음



* 체계적인 설계 과정 : 프롬프트를 설계하고 최적화가 중요
* 정밀성 : 정밀한 언어 선택과 구조화가 필요
* 반복적 개선 : 결과를 분석하고 프롬프트를 조정해야함
* 패턴과 원칙 등도 있음



LLM은 맥락에 아주 민감하여 동일한 질문이라도 앞뒤로 어떤 대화를 하고 추가 정보를 줬는지에 따라 다른 답변을 제공함. 

아무리 정교한 프롬프트를 사용해도 환각은 반드시 일어나므로 반드시 신뢰할 수 있는 출처로 교차 검증 해야 함. 



인스턴트 프롬프트 공식 (정교하지 않아도 원하는 결과물 얻기)

역할 부여 + 배경 정보 제공 + 작업 지시 + 출력 형식 정의





RAG : Retrieval-Augmented Genetation. 검색-증강-생성을 통해 외부 지식 베이스 검색 기능을 결합하여 최신 정보 제공, 신뢰성 향상, 출처를 통한 정보 제공을 가능하게 하는 기술 



모델이 답변을 생성하기 전에 **외부 지식 저장소(예: 벡터DB, 문서DB, 검색엔진)**에서 관련 정보를 찾아오고, 그 정보를 바탕으로 답변을 만들어내는 방식

**장점**

- 최신 정보 반영 가능 (LLM 학습 시점 이후의 데이터도 검색 가능)
- 사실성 향상 (hallucination 줄이기)
- 도메인 특화 가능 (예: 내부 문서, 매뉴얼, 의료 데이터 등)

**단점 / 과제**

- 검색 품질이 나쁘면 답변도 잘못될 수 있음
- 긴 문서를 어떻게 chunking 할지 전략 필요
- 프롬프트에 넣을 수 있는 토큰 한계 존재



LLM과 RAG를 통합하여 사내 특정 용도 시스템을 만들 수 있음

- ﻿﻿사내 업무 지원: 회사의 내부 문서를 검색하여 직원들의 질문 에 답변하는 시스템
- ﻿﻿학술 연구 지원: 최신 논문을 검색하고 요약하여 연구자들을 지원하는 시스템
- ﻿﻿고객 지원: 제품 매뉴얼이나 FAQ를 검색하여 고객 문의에 응 답하는 시스템
- ﻿﻿법률 자문: 판례와 법률 문서를 검색하여 법률 관련 질문에 정 확한 정보를 제공하는 시스템
- ﻿﻿의료 정보 제공: 의학 논문과 임상 데이터를 검색해 의료 정보 를 제공하는 시스템





프롬프트 패턴 

특징

* 일관성 : 일관된 방식으로 반응하거나 대처하는 방법 제공
* 반복 사용 : 일반적인 지침이나 절차 제공
* 구조화된 접근 
* 효율성 향상
* 기반 지식 확립



효율적인 대화를 위한 비법이 프롬프트 패턴



## 템플릿 패턴

함수형 프롬프트

```
#입력
[템플릿]= 사장님, 제가 추천하는 아이디어는 (괄호1)이고, 이 아이디어의 핵심 가치는 (괄호2)입니다. 추천하는 슬로건은 다음과 같습니다: (괄호3)

#처리
당신은 "CSR(Corporate Social Responsibility) 전문가"입니다. 식품 제조기업을 위한 CSR 아이디어를 발굴하고, 괄호를 전부 채워주세요. 특히 (괄호3)에는 임팩트 있는 멋진 슬로건을 포함해 주세요.


#출력
[개수]= 3개
```

핵심은 placeholder의 활용.

* (), [], {{}} 를 사용해야지 "" 를 사용하면 안됌

조건부 템플릿

```
(제품명) 사용 후기
종합 평가: (별점)

[별점이 4~5인 경우]
추천 이유: (주요 장점 3가지)
이런 사용자에게 추천합니다 : (타깃 사용자)

별점이 [1~3인 경우]
아쉬운 점 (개선이 필요한 경우 2가지)
이런 대안을 고려해보세요 (대안 제품1~2개)
```



## 대안 접근법 패턴

모든 대안과 해결책 찾아보기

```
#입력
[문제]= 팀 내에서 불화를 일으키는 대리급 개발자가 있습니다.
[방안]= 협업이 필요 없는 덜 중요한 작업을 맡기려고 합니다.

#처리
나는 대기업의 프로젝트 매니저입니다. 당신은 “세계 최고의 프로젝트 관리 전문가이자 나의 멘토”입니다. 당신은 내가 맡은 프로젝트에서 발생하는 여러 문제의 효과적인 해결 방안을 찾는 데 도움을 주어야 합니다.
1. [문제]를 해결하기 위해 [방안]을 고려하고 있습니다. 이를 포함해 문제를 해결할 수 있는 모든 대안을 찾아낸 후, 각각의 장단점을 알려주세요.
2. 모든 방안 중에서 가장 추천하는 것과 그 이유를 알려주세요.
```

기술 문제 해결에 유용한 패턴 

이 패턴시 사용시 모델 처리 단계

1. 문제 인식과 분석
2. 대안 탐색
3. 장단점 분석
4. 추천 제공

주의사항

* 해결하고자 하는 문제를 명확하게 정의해야 한다. 맥락을 충분히 제공하고, 배경 제약조건을 구체적으로 설명하는 것이 중요하다. 
* 평가 기준 제시를 통해 내 우선순위에 맞게 대안점들을 내놓음 
  * 예
  * 비용 효율성, 실행 난이도, 시간 소요, 성공 가능성 부작용 위험
* 다양한 확보를 위한 지시로, "일반적인 해결책 뿐만 아니라 창의적이거나 비관습적인 방법도 포함해줘 " 도 사용 가능 
  * 단기적 해결책과 장기적 해결책을 모두 고려해주세요도 간으
* 대안의 개수를 지정해서 다양한 탐색 가능 
  * 카테고리 별로 대안을 제시해주세요
    * 기술적 해결책
    * 프로세스 개선 방안
    * 인적 자원관리 접근법
    * 외부 자원 활용 방안

추가적으로 위험요소 분석 요청도 같이 할 수 있다.

* ) 각 대안의 주요 위험 요소와 이를 완화할 수 있는 방법도 함께 제시해주세요

```
#처리
당신은 “노벨상을 받은 물리학자이자 우주공학자"입니다. 나를 [대상]이라고 가정하고, [대상]의 지식, 배경, 관심사, 언어, 스타일을 고려하여 [질문]에 대한 맞춤형 답변을 제공해 주세요.
```

## 레시피 패턴 : 목표 달성을 위한 작업 단계 받기



```
<프롬프트>

#입력
[회사]= 10인 규모의 소프트웨어 스타트업
[목표]= 시공업체 선정 이전에 필요한 인테리어 계획 세우기
[식별된 작업]= 예산 수립, 공간 계획, 조명 계획, 일정 수립, 정기적인 유지보수


#처리
당신은 “사무실 인테리어 전문가”입니다. 당신은 사무실의 기능성과 미적 감각을 고려해 인테리어를 디자인하는 역할을 맡고 있습니다.
1. [회사]를 대상으로 [목표]를 달성하기 위해, [식별된 작업]에서 누락된 작업을 파악하여 추가하고, 불필요한 작업은 삭제합니다.
2. 필요한 모든 작업을 순서대로 정리해서 알려주세요.


#출력
[추가한 작업]
[삭제한 작업]
[전체 작업]= 순서, 작업 명, 설명을 표 형태로 표시합니다.
```

목표를 달성하기 위해 식별된 작업에서 누락된 작업을 파악하여 추가하고 불필요한 작업을 삭제합니다 순서대로 알려주세요가 레시피 패턴이다.

레시피 패턴 고려요소

* 목표 명확화 
  * 목표의 구체성 : 최종 결과를 구체적으로 명시. 웹사이트 제작보다는, 반응형 포트폴리오 웹사이트 제작
  * 범위 설정 : 1개월 내 완성 가능합 앱 개발 계획 처럼 범위 한정
  * 성공 기준 : 목표 달성 판단 기준을 '일 방문자 100명 이상 블로그 구축' 처럼 명시하면 효과적
* 맥락 정보 제공
  * 자원 제약 : 가용 예산, 제약 조건 등을 명시해서 범위를 좁힌다
  * 어디까지 기존 작업이 됐는지 명시한다
* 작업 식별 방식 지정 
  * 프로젝트 범위 정의, 요구사항 분석, 일정 계획 처럼 주요 단계를 나열
  * 작업 상세 수준을 명시. (주요 단계만 혹은 세부 하위 작업까지 모두)
* 출력 형식 지정
  * 구조화 방식 : 표, 목록, 번호 등
  * 포함 정보(소요 시간 자원 난이도
  * 시각화 요소도 달라할 수 있음 

## 뒤집힌 상호작용 패턴 : AI가 묻고 사용자가 답한다

대화 방식을 역전시켜 모델이 사용자에게 필요한 정보를 질문하도록 유도해서 최적의 답변 유도

```
<프롬프트>


#입력
[요청]= 사무실 동료 중에 오피스 빌런이 있습니다. 최선의 해결책을 알고 싶습니다.


#처리
당신은 “대기업의 직장 상담사”입니다. 당신은 직장 내에서 발생하는 다양한 문제의 해결책에 대한 상담을 제공하는 전문가이며, 나는 당신에게 조언을 구하는 대리 1년 차 직장인입니다.
1. 이제부터 [요청]을 수행하기 위해 필요한 질문을 내게 해주세요.
2. [요청]을 수행하기에 충분한 정보를 얻으면, 이를 기반으로 구체적인 결과물을 제공해 주세요.

```

## 인지 검증자 패턴 : 복잡한 문제를 더 잘 다루는 방법 

사용자가 제공한 질문을 토대로 필요한 하위 질문을 스스로 만들고 자신히 답한 내용을 종합하여 원래 질문에 대한 포괄적인 답변을 제공하도록 하는것

```
<프롬프트>


당신은 “천체물리학자 스티븐 호킹”입니다. 다음의 질문에 대한 정확한 결론을 도출하기 위해 질문을 다양한 세부 질문으로 나누어서 답변을 작성합니다. 모든 답변을 종합적으로 판단해서 결론을 작성해 주세요.
- 질문: 우주의 운명과 그 결말에 대해 알고 싶습니다.
```

- ﻿> 예)"각 하위 질문에 답한 후, 그 답변의 신뢰 수준을 평가하고, 어떤 제약이나 불완전한 점이 있는지도 함께 설명해 주세요."
- ﻿> 예)"결론을 내리기 전에, 중요한데도 간과된 측면이 있는지 다 시 한번 점검해 주시기를 바랍니다.”

* 위 두가지도 추가하면 더 좋다. 

## 질문 개선 패턴 : 질문을 질문하기

더 정확하고 유용한 답변을 얻기위해 LLM을 활용하여 질문을 구체화하고 개선하는 방법 

```
#입력
[질문]= "Z세대가 좋아할 만한 이벤트 아이디어로 어떤 것들이 있을까요?"

#처리
유용한 답변을 얻을 수 있도록 [질문]을 더 나은 버전의 질문으로 개선해 주세요. 질문에 풍부한 맥락을 반영하여, 더 구체적이고 자세한 질문으로 만들어 주세요. 그리고 개선된 질문에 대한 당신의 답변을 작성해 주세요.


#출력
[개선된 질문]
[어떻게 질문을 개선했는지 설명]
[질문에 대한 답변]

```

하나의 질문에 대해 여러 개의 개선된 버전을 요청하여 다양한 관점을 얻을 수 있다.

-> 예)"다음 질문을 서로 다른 3가지 방향으로 개선해 주세요. 각 각 다른 포인트와 접근법을 가지도록 해주세요: [질문]”

## 팩트체크 목록 패턴

모델이 스스로의 답변에 대한 신뢰도를 평가할 수 있게 만드는 패턴

```
<프롬프트>

당신은 "하버드 대학의 역사학과 교수"입니다. 다음의 질문에 대한 답변을 작성하고, 답변의 신뢰성에 큰 영향을 미칠 수 있는 핵심 사실들을 식별해서 "팩트체크 목록"을 생성합니다. 각 사실의 신뢰도를 확률(100% 만점)로 평가하고, 답변의 마지막 부분에 목록을 추가해 주세요.
- 질문: 중세 유럽의 기사도 문화는 어떤 사회적, 문화적 영향을 끼쳤나요?

```

상황과 목적에 따라 다양한 형태로 요청할 수 있다.

- ﻿예 "답변 내용 중 가장 논쟁의 여지가 있는 부분을 별도로 표 시하여 집중 검증이 필요한 부분을 알려주세요."
- ﻿> 예) "각 정보의 시간적 유효성을 표시해 주세요. (항상 유효/특 정 시기에만 유효/시간에 따라 변할 수 있음)"

* ~> 예) "해당 분야의 학계나 전문가 사이에서 합의된 정도를 표시 해 주세요. (광범위한 합의/부분적 합의/활발한 논쟁 중)"

## 아웃라인 확장 패턴: 복잡한 주제와 아이디어의 구조화, 글쓰기의 방향성을 제시하는 방법

```
#입력
```
